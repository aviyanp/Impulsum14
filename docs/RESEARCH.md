# Research and design provenance

Research checked on 2026-10-16 against source repositories, not inferred from project descriptions alone.

- [Upstream Impulsum14](https://github.com/Mk0M/Impulsum14), base commit `6f25423`: README TODOs, private local-profile model, manual HTTP byte parsing, fixed identity/session, tournament member order, season stubs and synthetic market internals.
- [limevevo/f14-localfut](https://github.com/limevevo/f14-localfut), `server/beta_identity.py`: reports from native parser traces explaining kickoff-stub crashes, buffer-before-version order, lowercase `progressdata`, division aliases and zero-based fixture rounds. This work supplied wire-contract evidence; its Python server implementation was not transplanted.
- The same repository's `server/fifa14-legend-catalog.v24013.json` supplied the 42-card historical Legends metadata and the explicit stock-PC identity limitation. It is copied to `FUTDB/legends.json`; its MIT license is retained at `third_party/f14-localfut-LICENSE.txt`. Referenced image URLs are metadata; no new portraits/models/game executables were downloaded.
- [KyroGeorge2/FIFA-14-Local-FUT](https://github.com/KyroGeorge2/FIFA-14-Local-FUT): parent project for the local-FUT compatibility work, especially terminal post-match reporting behavior.
- [ZamboniDevelopment/Zamboni3](https://github.com/ZamboniDevelopment/Zamboni3), `Components/Blaze/GameManager.cs` and `ServerGame.cs`: reference for peer setup notification sequencing and matchmaking grouping by `OSDK_gameMode`. Its NHL-specific topology/service behavior is not assumed to be FIFA compatibility. The new lobby service is independently implemented against the repository's vendored Blaze3 SDK.
- [Aim4kill/BlazeSDK](https://github.com/Aim4kill/BlazeSDK): the vendored TDF/Fire types already used by upstream. This change fixes nested-container reflection targets/arguments, unbounded announced allocations, recursive unknown-container handling, frame limits, bounded queues and plain TCP asynchronous sends on the existing stack.
- The repository's existing `impulsum14launcher/patches/CardsDLLzf.dll` was inspected without modification. Its ManagerQuest serializer at virtual address `0x10134070` and parser at `0x10135740` establish `/managerquest` with `entries: [{key:0,value:int32},{key:1,value:int32},{key:2,value:int32}]`. The enum string table reached by `0x101665c0` resolves `0xa8` to `entries`, `0xf2` to `key`, and `0x253` to `value`. This establishes the storage format, not the semantic meaning of its bits or a native reward contract. These opaque client values cannot authorize server coin payouts.

Design choices follow those findings: preserve PC wire encoding, isolate account state without rewriting all card serializers, serialize only within an account, commit one aggregate snapshot for wallet/inventory consistency, use bounded synthetic-market query windows, and keep platform-specific claims behind evidence. The compatibility matrix documents where published native trace evidence still needs reproduction with this C# implementation.
